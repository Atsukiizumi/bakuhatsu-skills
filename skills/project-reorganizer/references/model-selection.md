# 模型选择策略：可以询问，但不要因选择问题阻塞分析

## 默认策略

`model_policy: auto`

主 Agent 保留协调与最终判断；对明确、短小、只读的探索任务使用宿主可用的轻量模型；业务状态机、数据库一致性、架构边界与疑难风险使用更擅长推理的模型；最后由主 Agent 复核与整合。仅按工作难度和可验证的宿主能力选型，不用未经证实的模型别名。

| 策略 | 适用需求 | 分配方式 |
|---|---|---|
| `auto`（默认） | 用户无特别偏好 | 按复杂度和可用性决定，单 Agent 也可完成 |
| `economy` | 尽量节省费用/额度 | 更少的子智能体、轻量模型优先，重大问题升档核查 |
| `balanced` | 质量与效率兼顾 | 轻量探索 + 较强的核心审查 + 主 Agent 复核 |
| `quality` | 关键风险或高可信度审查 | 采用可用的高能力模型，对核心问题独立复核 |
| `manual` | 用户明确指定 | 按用户给出的角色→模型映射配置；不支持则告知并回退 |

## 何时问用户

- 用户主动提出想挑选模型、指定某个 Agent 运行在哪个模型上、或设置费用/时长上限：**必须遵守或说明无法满足**。
- 非常大型的全库审查、预期显著增加用量时，宿主支持提问的情况下可先问一次偏好；若用户没有回答或环境非交互，按 `auto` 继续。
- 常规的只读两三模块审查，不必专门询问；不因等待模型选项而停下整个任务。
- 如果可用模型列表未知，不要冒充已发现模型；让用户填具体名字或使用 `inherit`，并在运行时以宿主验证结果为准。

**推荐一次性问题**：

“我准备并行审查几个独立模块。你希望使用哪种模型策略：自动分配（默认）、成本优先、均衡、质量优先，还是指定主/子 Agent 的模型？”

## 模型来源与降级

1. 用户显式的模型选择（在宿主支持且模型被授权时）；
2. 运行环境实际可用的子 Agent 定义与每次调用参数；
3. 宿主/项目已配置的默认子 Agent 模型；
4. `inherit`：继承主 Agent；
5. 不支持切换时保留当前模型，并在报告中说明。

这是**行为意图优先级**，不是在不同运行器中必然相同的技术配置覆盖顺序。平台本身的优先级、允许名单、组织策略和权限永远生效。

## Codex 使用提示

- 自定义 Agent 文件位于项目 `.codex/agents/<name>.toml` 或个人 `~/.codex/agents/`；常见可用字段包含 `name`、`description`、`developer_instructions`，以及可选 `model`、`model_reasoning_effort`。
- 运行层在 `.codex/config.toml` 的 `[agents]` 可以设置并发上限、默认子 Agent 模型等；此设置不能靠 `SKILL.md` 本身完成。
- 若不在模板中写死 `model`，该子 Agent 能使用运行时的默认/继承策略，更方便用户选择。
- 不要在 agent 配置文件中试图覆盖主会话的 provider、沙盒、审批与 MCP 权限。

## Claude Code 使用提示

- 自定义 Agent 位于 `.claude/agents/<name>.md`，YAML frontmatter 可写 `model: inherit`、`model: sonnet` 等当前可用的别名或完整模型 ID。
- `model: inherit` 使自定义 agent 默认跟随主模型；如需单独指定，可通过宿主支持的单次委派参数或 agent 文件选模型。
- `skills:` 可预加载子 Agent 必须用到的技能；主 Agent 应避免向所有子 Agent 注入大量无关说明。
- 存在组织允许名单和全局设置时，模型选择以实际运行结果为准。

## 报告要求

输出“计划模型/实际使用模型（如可知）/替代原因/子任务状态”。如果无法观测实际子 Agent 模型，记录 `unknown`，不推测。不要声称自己能跨厂商切换某模型，除非用户的宿主确实提供那个模型。
