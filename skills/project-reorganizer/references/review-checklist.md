# 软件工程审查清单

只报告能从仓库证实或标注为待验证的事项。

## 结构与依赖
- 模块职责、层次依赖、循环引用、重复业务规则、DTO/领域实体混用。
- UI/API/设备输入到领域逻辑与持久化的真实调用路径。
- 设计文档是否与当前实现一致。

## 数据正确性
- 库存数量、批次和状态更新是否具备正确的事务/并发控制？
- 唯一性约束、幂等键能否防止同一业务事件被处理多次？
- 外部系统失败后是否有补偿、重试、对账和可恢复状态？
- 拆箱/合箱/部分收发是否保留来源与去向追踪？

## 系统稳定性
- 共享状态、异步任务、事件订阅、UI 线程、队列、文件/串口/COM 资源释放。
- 日志是否具有业务关联编号并不会意外泄露凭证？
- 是否有适用于目标环境的测试、备份、部署与回滚？

## 证据级别
- 已确认：`path:line` + 可解释的执行路径，条件允许时可复现。
- 高概率：代码依据 + 预期触发条件 + 进一步验证方法。
- 待确认：明确缺失的信息，不描述成已存在的 bug。
