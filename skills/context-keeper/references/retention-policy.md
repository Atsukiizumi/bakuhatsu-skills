# 记忆保真与层级保留策略

## 关键判定

对于每条信息依次判断：是不是用户约束；会不会改变下一步代码行为；是否尚在活跃工作；有没有不可恢复的唯一证据；是否可引用原文位置。先定级再摘要，而不是先删短句。

## P0/P1：高保真

- **P0**：最新用户明确要求、产品规则、边界条件、接口契约字段、数值和单位、不可跳过的审批或权限、迁移与库存一致性要求。对关键业务表达保留原意，必要时保留精确字段名、枚举、版本号、错误码、主键。
- **P1**：本分支任务目标、当前未提交/未跟踪更改、执行结果（命令+状态）、阻塞原因、可执行的下一动作；失败的实验不能写成通过。

## P2/P3/P4：减重

- **P2**：决策写成「最终采用什么 / 为什么 / 排除了什么 / 指向哪个 ADR 或代码证据」。需跨会话长期使用的转移到 docs/adr；交接只引用。
- **P3**：旧阶段任务摘要一行带原始路径；不必重复历史上下文。
- **P4**：重复的大日志、无效搜索、没有结论的中间推导不进入摘要；原始文件是否清理另行审批。

## 不允许的压缩

- 不将“建议/计划”写成“已实现”；不把“编译通过”写成“测试通过”；不把“本地测试通过”写成“生产验证通过”。
- 不将 `400 / 1000` 缩写成“支持部分数量”而丢掉本次收货规则。
- 不将 `项目只读/禁止修改代码` 压缩成“注意安全”。
- 不保存密码、令牌、私钥、密钥材料或完整敏感日志。

## 尺寸目标

INDEX 30–40 行；ACTIVE 通常 60–100 行；HANDOFF 通常 100–180 行。这些都是**可调整的参考值**，不是允许删掉 P0/P1 的硬上限。若 P0/P1 过多，分出权威 docs 并以路径引用，不机械截断。

## 滚动更新法

旧 ACTIVE/HANDOFF + 当前新事实 delta → 对证据逐项核查 → 保留仍有效的约束 → 清除已完成的活跃任务 → 将永久知识移交 ADR → 写新 ACTIVE/HANDOFF。历史变更留 Git 或获准归档，不复制所有旧 handoff。
