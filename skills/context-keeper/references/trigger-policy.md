# 主动压缩触发策略

## 信号来源

优先级：宿主公开的真实 token 统计 > 宿主主动压缩事件 > 模型自行观测的里程碑/工具输出量 > 会话主观体感。不要根据文件字符数推定真实 token 使用率，也不要把提示缓存命中率视为活跃上下文占用率。

| 真实使用率 | 默认动作 |
|---|---|
| <50% | 继续任务，控制工具输出规模 |
| 50–65% | 在下一个里程碑做增量检查点 |
| 65–80% | 做检查点/语义验证；准备在安全边界压缩 |
| >80% | 尽快收束原子操作，进行 P0/P1 保存和原生压缩（若可用） |

阈值为建议启动值，不是模型固定限额；真实窗口大小、系统保留区及宿主自动压缩阈值优先。

## 无法获得 token 数据时

不显示假占用百分比，以事件触发：阶段交付、任务切换、模型切换、连续海量工具输出、多次反复读取、已否决方案重新出现、用户明确要求准备新会话。推荐只在发生新 delta 时写入；无需每轮无意义更新。独立长期工作可以在每次重要工具批次后做短检查，而不重新总结整个历史。

## 抑制和保护

- 当前正在执行迁移、事务、关键异常定位时，不打断到危险中间状态；可先保存极短保护检查点。
- 避免接连压缩：距离上次检查点很近且没有有效新信息时不重复写文件；不可知真实 token 时不要推测“已经释放”。
- 阈值触发与检查点写入失败时，优先停止删除/清理动作；报告风险。
- PreCompact Hook 触发点可能过晚，不能取代日常检查点维护。
- 允许 Subagent 压缩调查输出：返回「结论 / 证据 / 不确定项 / 下一步」；子代理不被授权覆盖核心记忆。
