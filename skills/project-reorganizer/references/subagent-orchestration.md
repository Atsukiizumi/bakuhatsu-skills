# Sub-agent 编排协议（宿主无关）

## 1. 权限与能力

- 主 Agent 可以自主**发起只读**子任务，但只能使用宿主已暴露的工具。没有子智能体工具时退化为单线程检查。
- 委派遵守用户意图、文件范围、网络/终端限制及 audit/plan/implement 模式；并行不代表自动获得写入或生产操作权限。
- 在宿主有原生设置可控制的情况下，默认最大同时运行 3 个子 Agent。这个数量只是建议值，不能覆盖系统/账户实际限制。
- 默认树深 1：只有主 Agent 可再分派。确有充分理由且用户许可、宿主支持时再启用更深层嵌套，以免递归扩张和失控成本。
- 不要为每个源文件都开一个 Agent；按独立业务域/问题域分配。小于一个函数/一个小文件的单任务优先主 Agent。

## 2. 编排策略

1. 主 Agent 建立仓库模块清单和任务依赖 DAG，锁定“必须先知道什么”。
2. 对可并行任务分配互不重叠的目标/范围，标记 read-only，最多一轮并行 2～3 个任务。
3. 每个子任务提供统一任务合同（见下）。
4. 收集结构化结论，补查缺失证据和跨模块边界。
5. 主 Agent 单点汇总，不把子 Agent 结论原封不动拼成矛盾报告。
6. 若模型切换/委派能力不支持，说明实际执行情况，不伪称模型或子 Agent 运行成功。

## 3. 委派合同（每次派发应包含）

```text
Task ID: ARCH-01
Role: architecture-reviewer
Goal: 还原 API → 应用服务 → 领域逻辑 → 仓储的调用链，找出真实耦合点。
Scope: src/Api, src/Application, src/Domain, src/Infrastructure
Mode: audit / read-only
Out of scope: 代码修改、数据库访问、外网写操作、其他仓库
Inputs: 技术栈、模块清单及当前项目约束（只提供完成任务所需内容）
Questions: 哪些层互相调用？哪段代码证明？哪里违反职责边界？
Evidence: 仓库相对路径 + 行号范围；不能验证则标“待确认”
Deliverable: 简短发现表 + 主要调用链 + 未覆盖内容
Finish: 完成任务范围内检查即返回，不递归继续分派
Model: user-selected / inherited / auto (仅宿主支持时指定)
```

## 4. 子智能体回复格式

| 字段 | 说明 |
|---|---|
| `task_id` | 和派发一致 |
| `status` | `completed / partial / failed / unsupported` |
| `scope_checked` | 已分析的模块或路径 |
| `findings` | 问题清单：现象、严重程度、置信度、影响、`path:line` |
| `artifacts` | Mermaid 片段、流程表等必要的精简结果 |
| `gaps` | 无法访问、无证据或未阅读的范围 |
| `model_used` | 仅可确认时填写；否则 `unknown` |

证据不足的结论不得升级为“确认缺陷”。跨 Agent 重复报告要归并，冲突交由主 Agent 查证。关键 P0/P1 至少由主 Agent 查验真实代码位置；必要时安排第二个 Agent 独立复核。

## 5. 只读与写入隔离

- `audit` / `plan`：所有任务只读；如工具支持专门的只读子 Agent，优先使用。子 Agent 的文字承诺不是操作系统级隔离措施，主 Agent 应保持宿主沙盒/审批约束。
- `implement`：必须有明确批准的任务卡。尽可能按文件所有权隔离任务；如宿主支持 worktree，可让并行写入 agent 使用独立工作树。归并前逐项审核 diff、运行能安全执行的测试，并且保留原始未提交改动。
- 非常规开销（大量子 Agent、强模型、长时间外部调用）或超出授权的配置变更，应询问用户，不擅自扩大。
- 不自行更改用户的模型账户设置、计费设置、系统/全局 harness 配置或权限开关。

## 6. 针对代码库梳理的示例

主 Agent 先建立项目地图，然后根据实际模块调度：

- `ARCH-01`：后端分层与跨层调用（只读）。
- `BUS-02`：入库、出库、业务状态与 ERP 边界（只读）。
- `DATA-03`：数据库实体、事务与库存一致性（只读）。

完成后对入库→库存→ERP 跨子任务链路进行交叉验证，最终在报告中说明数据一致性结论是否经过代码确认。

## 7. 提问策略

首选最小打断：用户没明确选择模型时，`auto` 可直接启动可用模型做常规只读审查。如任务规模会明显影响时间或计费，可以在执行前一次性问：

> “本次适合使用 3 个 Sub-agents 并行梳理。模型策略选自动分配、成本优先、质量优先，还是由你指定？不选择则默认自动。”

用户已指定模型或选择时不要重复询问；不支持人机交互就直接执行默认配置。不得向用户展示实际不可用的型号当作可选项。
