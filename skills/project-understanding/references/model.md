# 项目模型

阅读规则在 `references/reading.md`。本文件只规定模型里有什么。

## 文件

写到目标仓库的 `docs/project-model/`。某一视图没有证据时不建对应文件，并在索引的未知项里说明。

| 文件 | 内容 |
| --- | --- |
| `00-index.md` | 后续 Agent 的唯一入口 |
| `01-features.md` | 功能候选清单和功能卡 |
| `02-docs.md` | 文档对照表。第三遍跳过时不建 |
| `03-structure.md` | 开发视图，以及有领域类型时的逻辑视图 |
| `04-behavior.md` | 进程视图里的关键流程 |
| `05-data.md` | 数据视图。没有持久化证据时不建 |
| `06-analysis.md` | 4+1 覆盖和追溯 |

## 索引

`00-index.md` 控制在约 40 行：目标、可运行单元、技术栈、阅读顺序、覆盖（已读 / 推断 / 未读）、未知项。

后续 Agent 先读索引，再读与当前任务相关的功能卡，然后按需打开结构或数据文件。

## 视图

用 Kruchten 4+1。每张图都要能指到代码或配置。

| 视图 | 写在 | 何时画 |
| --- | --- | --- |
| 场景 | `01-features.md` | 始终有功能树。卡片来自阅读的第二遍 |
| 开发 | `03-structure.md` | 一张组件图，表示模块职责和依赖方向 |
| 逻辑 | `03-structure.md` | 代码里有明确领域类型时才画类图，按类型而不是按文件 |
| 进程 | `04-behavior.md` | 只给跨模块或改变持久状态的核心流程画时序图或状态图 |
| 物理 | `06-analysis.md` 的一节 | 仓库里有部署或运行配置时才写 |
| 数据 | `05-data.md` | 有建表、迁移或 ORM 映射时画 ER。推断的关系单独标明 |

图的上限：1 张组件图、1 棵功能树、有持久化时 1 张 ER。时序图或状态图只画核心流程。用 Mermaid。

## 功能卡

每张卡使用这些字段：编号、名称、参与者、目标、触发入口、主流程、例外、业务规则、读写的数据、涉及模块、相关图、证据 `path:line`、状态。

状态只有三种：

| 状态 | 含义 |
| --- | --- |
| `confirmed` | 第二遍已读完。没有相关文档，或相关文档的对照结果是 `matches` |
| `inferred` | 第二遍还没读完，或已经读完但相关文档的对照结果不是 `matches` |
| `unknown` | 知道有这个入口，但行为还没建立 |

文档五种对照结果的定义在 `reading.md`。对不上的陈述不写入卡片正文。

## 分析

`06-analysis.md` 只记录 As-Is：哪些视图有证据、依赖方向、从功能到代码到数据到测试的追溯。没有测试就写成事实。

不写修复方案、优先级和重构阶段。
